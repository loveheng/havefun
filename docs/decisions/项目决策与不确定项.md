# 项目决策与不确定项（PM 确认入口）

> 本文是 PM 确认的唯一入口：PM 直接在「待确认项」各行的「PM 确认」列批注（同意默认值写「确认」，不接受就写要什么）。批注后由辅助工具按本文回填源文档、刷新 PM 域派生件；其他文档不重复承载待确认清单，只放指向本文的指针。
>
> **代号说明**：F=已确认事实；D=结构性决策（M0 冻结门，批完才进冲刺）；N=执行层决策（默认值是建议值，确认后可调）。「行业参考」指借自外部公开产品的惯例值，不是本项目的结论。
>
> 细粒度数值参数（盲盒公示精度、风控阈值、抽成比例、提现参数、通知阈值、违规处置阶梯等）不在本文单列——PM 直接在[缺失补全方案](../requirements/缺失补全方案.md)与[数据闭环推演](../requirements/数据闭环推演.md)对应小节内批注即可，本文只收需要确认的决策项。

## 批注后怎么流转

1. PM 在「PM 确认」列批注（或直接改「现行默认值」列）；
2. 辅助工具按批注把结论回填到对应源文档（requirements 域），源文档刷新 `updated`；
3. 源文档实质修改后，辅助工具刷新对应 PM 域派生件（派生要求见 xiaolequ-docs skill）；
4. 已确认的事项移入上节「已确认事实」表（新增 F 编号），本表对应行标「已确认 + 日期」留档，不删除。
