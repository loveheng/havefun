## 端与交付物清单
（来源：docs/requirements/端与交付物清单.md，updated 2026-10-13）


- **端总数：2 个自研端（3 个交付物）+ 3 个外部依赖端**——用户端 APP（iOS/Android 双平台）+ Web 运营后台；客服坐席首版用后台替代，不独立建端。
- **工作包划分**：本文即开发团队的任务划分表——App 双平台各一个工作包、后台一个工作包、三方接入三条线（运营商/支付/机审）。
- **外部端不自研但决定闭环**：流量域（运营商）与资金域（支付通道）的接口不通，对应功能只能降级上线（见[自建服务难度评估](自建服务难度评估.md) §六）。
- **需要你确认**：已确定（2026-10-13）——**后台管理页面由后端直接接管，不设常驻前端；常驻开发组 3 后端 + 2 App，前端机动，UI 机动不固定（按需支持，不驻场）**；剩余待确认项仅「iOS/Android 同步交付还是分阶段」。
- **排期标准（2026-10-13 定）**：开发团队为**兼职投入，人均每周 3 天**（投入上限档）；本档下排期按满负荷测算，排期为**一期 MVP 约 5.5~6 个月、全量约 8~9 个月**。所有月数均以「人均每周 3 天」为前置条件，投入降档即重排。

## 数据闭环推演
（来源：docs/requirements/数据闭环推演.md，updated 2026-10-13）


- **判断**：需求文档把「界面上的数字」都画出来了，但**一半以上的数字没有交代来源或去处**——最典型的是碎银：8 个获取渠道无一有数值与上限，8 个消耗出口无一有定价规则。
- **三类未闭合**：①无来源（优惠券/电子券、商户角色、餐厅点餐、任务中心）；②无去处（扫一扫）；③有来源有去处但中间规则缺失（碎银兑换率之外的定价、二手资金是否过平台）。
- **闭合优先级**：碎银账本规则 → 资金链路过不过平台 → 校园网数据接口——这三条不闭合，开发写不出第一行结算代码。

## 自建服务难度评估
（来源：docs/requirements/自建服务难度评估.md，updated 2026-10-13）


- **判断**：真正「必须自己写且难」的只有四块——**校园网/校园卡对接、资金链路、碎银账本、跑腿交易闭环**；其余大部分服务（IM/推送/短信/机审/存储）**能买不建议自建**。
- **最大风险**：校园网对接不是难在开发，是难在**数据源可能根本拿不到**（依赖运营商/校方接口）——这是排期前必须先验证的第一件事。
- **合规门槛**：资金链路（支付/提现/二清）与内容审核是上架前提，不是优化项。
- **需要你确认**：① 校方/运营商接口能否获取（决定核心价值是否成立）；② 资金走持牌通道还是劝阻人民币链路；③ 三方服务选型（IM/机审）。
