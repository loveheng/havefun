# 校乐趣 · 结论汇总（给 PM）

> 生成日期：2026-10-13。由 `toolbox run pm-conclusions` 机械汇总 docs/ 与 internal/ 共 13 处「给 PM」结论小节后经辅助工具归并去重而成；细节以各源文档为准（每节末标注来源与 updated 日期）。

## 总体判断（一段话版）

需求文档 1.0 是合格的梳理稿（17 章 + 80 张设计稿，用户侧 UI 全链路清晰），但**不建议直接开工**。离可开发的完整需求还差三层：**后台管理层、平台层、非功能层**，其中三个平台层卡点是硬阻塞——①校园网/校园卡对接方案空白（工作量最难预估）、②资金合规方案缺失（法律底线）、③UGC 内容审核缺失（上架前提）。这三条不定下来，工作量与排期都是虚的。

## 三个 P0 卡点（开工前必须解决）

| # | 卡点 | 性质 | 需要你确认 |
|---|------|------|-----------|
| 1 | **校园网/校园卡对接** | 不是难在开发，是**数据源可能根本拿不到**（依赖运营商/校方接口）——排期前必须先验证的第一件事 | 校方/运营商接口能否获取（决定核心价值是否成立） |
| 2 | **资金链路合规** | 平台涉及人民币归集与提现，属法律底线；走「担保交易」还是「不碰钱」、持牌通道还是劝阻人民币链路，需确定 | 资金链路方案二选一；碎银↔人民币换算 1两=1元 是否接受 |
| 3 | **UGC 内容审核** | 影响所有发布模块（社区/表白墙/二手/跑腿），不过审无法上架；缺失补全方案已给出默认规则建议（先发后审+机审） | 审核模式与 SLA 按缺失补全方案『审核模式』批注确认 |

另有一组数据面问题：碎银 8 个获取渠道无一有数值与上限、8 个消耗出口无一有定价规则——**缺失补全方案**已给出行业基准默认值（确认后可调），另有三个结构性决策需确认：①资金链路（同上）；②换算汇率（同上）；③孤儿功能（餐厅点餐/扫一扫/商户客服）归二期（2026-10-13 确认），需求定义随二期补齐。其余默认值同样要你逐条批注后才进开发（清单见缺失补全方案文末『PM 确认清单』）。

> 来源：`docs/requirements/缺失补全方案.md`、`docs/requirements/自建服务难度评估.md`、`docs/requirements/数据闭环推演.md`

## 人力与排期（已确定）

- **编制**：常驻 3 后端 + 2 App（跨端框架，分包并行）——后台管理页面日常由后端接管（页面初稿借助辅助工具生成），复杂交互页（审核工作台等）由前端在 S3 冲刺内进场约 2 周完成；UI 不驻场但交付节点固定（M0 交切图、收尾走查约 1 周），前端与 UI 接入时间已写进里程碑，见[排期与里程碑计划『前端与 UI 接入安排』](排期与里程碑计划-给PM.md)（2026-10-13 确定编制，2026-10-14 固定接入节点）。客服坐席建议首版用后台替代、不独立建端（待确认）。
- **兼职前提（必须先读）**：开发团队为**兼职投入，人均每周 3 天**，所有月数均以此档为前置条件，投入降档即重排（详见[排期与里程碑计划『投入前提与工期约定』](排期与里程碑计划-给PM.md)）。
- **排期**：兼职档（人均每周 3 天）下**一期 MVP 约 6.5~7 个月、全量约 9~10 个月**，以[排期与里程碑计划](排期与里程碑计划-给PM.md)为准。服务端单线（业务 + 后台模块、含 20% 测试）收口约 6.5~7 个月，是项目时间里的一部分（周期已含必要余量，不单列拆分），详见[工期评估-按功能点](工期评估-按功能点-给PM.md)。
- **外部依赖**：等待期与降级方案见[排期与里程碑计划『外部依赖与周期说明』](排期与里程碑计划-给PM.md)；新增需求按变更走二期清单。

## 能买则买（不自建清单）

IM、推送、短信、机审、存储均可采购，选定供应商后为集成工作，不阻塞开发。真正「必须自己写且难」的只有四块：校园网/校园卡对接、资金链路、碎银账本、跑腿交易闭环。自建顺序：账号体系 → 碎银账本（含风控）→ 商城/社区 → 跑腿闭环。**需要你确认：三方服务供应商选型（IM/机审）。**

> 来源：`docs/requirements/自建服务难度评估.md`

## 合规底线（非可选项，上架前提）

盲盒概率公示、账号注销、先发后审+机审、提现实名——属上架前提（合规硬要求），缺失补全方案已内嵌为默认规则，具体数值与流程仍需按『PM 确认清单』批注确认。

> 来源：`docs/requirements/缺失补全方案.md`
