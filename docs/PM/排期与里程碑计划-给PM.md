# 校乐趣 · 排期与里程碑计划（给 PM）

> **代号说明**：M0=启动前准备阶段（选型与需求冻结），M1=一期上线，S1~S3=第 1~3 个开发冲刺，T0=M0 完成日；MVP=最小可用版本（首版上线范围）；P0/P1/P2=问题优先级（P0 最优先）；§=原始《需求文档.md》的章节号（本文不给自己编号）。

## 结论（给 PM）

- **总约定**：开发团队为**兼职投入，人均每周 3 天**；本计划全部周期以此档为前置条件——投入降档即重排，投入升档时能压缩多少，重新评估后再定。
- **周期**：一期 MVP 约 **6.5~7 个月**上线，全量约 **9~10 个月**（一期 8 功能包 + 二期 4 包，见『分期范围』）；周期已含必要余量，不单列拆分。
- **测试工序**：服务端含 20% 测试时间（资金链路、跑腿状态机、碎银账本全量回归，见[工期评估-按功能点](工期评估-按功能点-给PM.md)），后端线收口约 6.5~7 个月，仍在项目窗口内；App 端测试由开发自担，计入各冲刺。
- **最大不确定项在外部**：运营商/校方接口申请、支付资质审批按以往经验通常需要 1~3 个月，进度由外部机构决定，联调窗口按实际到位时间安排（见『外部依赖与周期说明』）。
- **人力**：常驻 3 后端 + 2 App（跨端一套代码双平台，分包并行）；前端与 UI 均有**固定接入节点**（不是随叫随到的机动支援，见『前端与 UI 接入安排』）；增员建议仅 **+1 测试**（专保资金链路与跑腿状态机回归），加后端无收益（两条线均无余量）。
- **需要你配合**：M0 进入冲刺前批完八项待确认清单（见[项目决策与不确定项](../decisions/项目决策与不确定项.md)『结构性决策 D1~D8』，PM 直接在该文档批注），未冻结不进冲刺。

## 投入前提与工期约定

1. 团队投入为兼职制，常态档 **人均每周 3 天**（约 60% 投入，按满负荷测算）；投入档位变动确认后，工期相应重排。以上周期**已含必要余量**，用于吸收外部环节波动与一般性返工，不单列拆分。
2. 新增需求一律走变更流程排入二期清单，不在本计划周期内吸收；变更工作量另行评估排期。
3. M0 起点以八项待确认清单批完之日计。外部环节的等待期与降级方案见『外部依赖与周期说明』。

## 里程碑总览（一期 MVP，T0 = M0 启动日）

| 里程碑 | 内容 | 出口标准 | 周期 |
| --- | --- | --- | --- |
| **M0 选型与冻结** | Flutter/RN 确定、资金 A/B 确认、三方对接函发出、需求冻结 | 八项待确认清单批完；运营商对接函已发 | **3 周** |
| **S1 冲刺一** | 后端：账号体系/碎银账本地基；App：账号+首页+碎银；**iOS 壳包提前提交一次过审，验证审核要求** | 登录/碎银获取消耗闭环可演示 | 7 周 |
| **S2 冲刺二** | 后端：跑腿状态机/担保交易/订单；App：发布+校友圈+订单+消息 | 核心交易闭环联调通过 | 7 周 |
| **S3 冲刺三** | 后台：内容配置+用户管理+审核工作台；App：跑腿双角色页；全员联调 | MVP 全功能回归通过 | 7 周 |
| **收尾** | 提审上架、灰度、缺陷收敛 | 双端过审、可对外发布 | 3~4 周 |
| **外部衔接窗口** | 运营商/校方接口、支付资质到位后的联调与切换（到位早则并入前序冲刺，不另占周期） | 三方联调通过 | 2~3 周 |
| **M1 一期上线** | | | **T0 + 6.5~7 个月** |
| **二期补全** | 花名册/盲盒/校园活动/收藏报名邀请 + 报表/风控/财务对账完善/IM | 全量功能 | 再 ~3 个月 |

- 并行线：后端 A（账本/订单/跑腿）、后端 B（账号/审核/后台管理面）、后端 C 兼架构（资金链路/三方接入）三人无依赖冲突；App-1（核心闭环包）、App-2（内容与交易包）分包并行互为 review。
- 排期细节与人力分工依据见[端与交付物清单『开发组人力配置』](../requirements/端与交付物清单.md)。

## 前端与 UI 接入安排

前端与 UI 不驻场，但接入时间固定在里程碑里，不按需临时叫：

| 人员 | 接入节点 | 工作内容 |
| --- | --- | --- |
| UI | M0 期间（3 周） | 一期 8 包设计稿裁剪与切图标注全部完成，各冲刺开工前对应稿已可用 |
| UI | 收尾阶段（3~4 周内） | 全量视觉走查约 1 周（提审前修订） |
| 前端 | S3 冲刺内进场约 2 周 | 审核工作台等复杂交互页，时间与后端 B 的 S3 排期一致，投入按实际工作天数核算 |

- 执行方式：后台管理页面日常由后端 B 接管，页面初稿借助辅助工具生成；前端只负责复杂交互页这一类工作。
- 财务对账等二期复杂交互页的前端介入随二期排期另定。
- 以上窗口与常驻团队同为兼职投入档（人均每周 3 天）；节点前移或加长需同步调整总排期。

## 外部依赖与周期说明

| 依赖 | 等待期 | 卡住时的降级 |

## 计划维护

- 本计划按里程碑滚动维护：每个冲刺出口刷新状态与偏差；外部进度发生变化时更新『外部依赖与周期说明』并同步调整排期。
- 变更记录追加于文末，不删除历史条目。
