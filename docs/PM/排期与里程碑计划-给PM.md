# 校乐趣 · 排期与里程碑计划（给 PM）

## 结论（给 PM）

- **总约定**：开发团队为**兼职投入，人均每周 3 天**；本计划全部周期以此档为前置条件——投入降档即重排，升档时重新评估后再定，不保证按比例压缩。
- **周期**：一期 MVP 约 **5.5~6 个月**上线，全量约 **8~9 个月**（一期 8 功能包 + 二期 4 包，见 §三）。
- **最大不确定项在外部**：运营商/校方接口申请、支付资质审批按以往经验通常需要 1~3 个月，进度由外部机构决定，联调窗口按实际到位时间安排（见 §四）。
- **人力**：常驻 3 后端 + 2 App（跨端一套代码双平台，分包并行），前端机动，UI 机动不固定（按需支持，不驻场）；增员建议仅 **+1 测试**（专保资金链路与跑腿状态机回归），加后端无收益（两条线均无余量）。
- **需要你配合**：M0 进入冲刺前批完八项待确认清单（见[待确认事项台账](../../context/pending-confirm.md)），未冻结不进冲刺。

## 一、投入前提与工期约定

1. 团队投入为兼职制，常态档 **人均每周 3 天**（约 60% 投入，按满负荷测算）；投入档位变动确认后，工期相应重排。
2. 运营商/校方接口申请、支付资质审批、苹果审核等外部环节按以往经验通常需要 1~3 个月，联调窗口按实际到位进度安排。
3. 新增需求一律走变更流程排入二期清单，不在本计划周期内吸收；变更工作量另行评估排期。
4. M0 起点以待确认事项台账批完之日计。

## 二、里程碑总览（一期 MVP，T0 = M0 启动日）

| 里程碑 | 内容 | 出口标准 | 周期 |
| --- | --- | --- | --- |
| **M0 选型与冻结** | Flutter/RN 确定、资金 A/B 确认、三方对接函发出、需求冻结 | 八项待确认清单批完；运营商对接函已发 | **3 周** |
| **S1 冲刺一** | 后端：账号体系/碎银账本地基；App：账号+首页+碎银；**iOS 壳包提前提交一次过审，验证审核要求** | 登录/碎银获取消耗闭环可演示 | 6 周 |
| **S2 冲刺二** | 后端：跑腿状态机/担保交易/订单；App：发布+校友圈+订单+消息 | 核心交易闭环联调通过 | 6 周 |
| **S3 冲刺三** | 后台：内容配置+用户管理+审核工作台；App：跑腿双角色页；全员联调 | MVP 全功能回归通过 | 6 周 |
| **收尾** | 提审上架、灰度、缺陷收敛 | 双端过审、可对外发布 | 2~3 周 |
| **M1 一期上线** | | | **T0 + 5.5~6 个月** |
| **二期补全** | 花名册/盲盒/校园活动/收藏报名邀请 + 报表/风控/财务对账完善/IM | 全量功能 | 再 ~3 个月 |

- 并行线：后端 A（账本/订单/跑腿）、后端 B（账号/审核/后台管理面）、后端 C 兼架构（资金链路/三方接入）三人无依赖冲突；App-1（核心闭环包）、App-2（内容与交易包）分包并行互为 review。
- 排期细节与人力分工依据见[端与交付物清单](../requirements/端与交付物清单.md) §6。

## 四、外部依赖与周期说明

| 依赖 | 等待期 | 卡住时的降级 |
| --- | --- | --- |
| 运营商/校方接口 | 按以往经验 1~3 个月 | 流量数据人工月度导入；卡状态静态提示；碎银主渠道改任务/广告渠道 |
| 支付资质（商户号/分账） | 与运营商并行 | 降级方案 B「不碰钱」，提现/余额模块下线 |
| 苹果审核 | 每次提审 1~7 天 | 壳包 S1 即提交，提前消化隐私清单/Apple 登录问题 |

## 五、计划维护

- 本计划按里程碑滚动维护：每个冲刺出口刷新状态与偏差；外部进度发生变化时更新 §四并同步调整排期。
- 变更记录追加于文末，不删除历史条目。
