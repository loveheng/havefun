# 工期评估（按功能点）· 给 PM

> **代号说明**：★=一期 MVP，☆=二期；后端 A / B / C = 三名服务端开发（A 核心业务、B 平台与后台页面、C 资金与三方接入）；「服务端工期」已含 20% 测试时间。

## 结论（给 PM）

> **读法说明**：本文只算**服务端**——3 名后端承担的业务模块 + 后台模块、含 20% 测试；**项目总排期（含 M0 选型、App 端开发、上架收尾）以[排期与里程碑计划](排期与里程碑计划-给PM.md)为准**。一期 6.5~7 个月是整个项目的时间，本文的一期服务端净开发 4~4.5 个月是其中的一部分，两者是包含关系。

- **判断**：业务模块 + 后台模块全部功能点，三人并行、人均每周 3 天投入、含 20% 测试，**服务端线收口约 6.5~7 个月**；一期服务端功能点约 4~4.5 个月完成，二期功能点集中在第 6~7 个月收尾。
- **计法**：各功能点工期不相加，总工期按最长的单线计——后端 A 约 6.5~7 个月，后端 B 约 6~6.5 个月，后端 C 净开发约 5 个月。外部环节与开发并行安排（等待期与降级方案见[排期与里程碑计划『外部依赖与周期说明』](排期与里程碑计划-给PM.md)）。
- **前提**：3 名后端、人均每周 3 天投入，升档/降档全部数字重排（投入档约定见[排期与里程碑计划『投入前提与工期约定』](排期与里程碑计划-给PM.md)）；20% 测试为正式工序（全量回归，由开发承担）；后台页面统一由后端 B 实现（Vue + Element，初稿借助辅助工具生成），审核工作台等复杂交互页由前端在 S3 冲刺内进场约 2 周完成（见[排期与里程碑计划『前端与 UI 接入安排』](排期与里程碑计划-给PM.md)）。功能点与分工见[开发区域划分](../requirements/开发区域划分.md)。
- **产能状态**：工作量贴近窗口产能上限——外部环节延期、需求新增、返工都会推迟总工期；新增需求建议进二期清单。
- **待确认**：无新增，直接按此排期。
