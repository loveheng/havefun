# 校乐趣 · 项目说明（给 PM）

> 本文是给 PM 的一页纸总览：全局判断、已确定、待确认、去哪找细节。各节均为其他域文档的派生摘要，出处随文标注。

## 一、项目一句话现状

需求文档 1.0 是合格的梳理稿（17 章 + 80 张设计稿，用户侧 UI 全链路清晰），但**不建议直接开工**——离可开发的完整需求差三层（后台管理层/平台层/非功能层），其中三个平台层卡点是硬阻塞；方案侧已把「怎么补」全部做完（默认规则 + 默认数值），现在卡的是**你的 8 项确认**（见 §三）。详见[需求文档评估](../requirements/需求文档评估.md)、[缺失补全方案](../requirements/缺失补全方案.md)。

## 三、待你确认的 8 项（M0 冻结门，批完才进冲刺）

1. **校园网/校园卡接口可达性**（全项目最优先——数据源拿不到则核心价值降级）
2. **资金链路方案**：担保交易（持牌分账）还是不碰钱
3. **碎银↔人民币换算** 1两=1元 是否接受
4. **孤儿功能处理意见**（餐厅点餐/扫一扫/商户客服/优惠券，已有建议）
5. **iOS/Android 同步交付还是分阶段**
6. **三方服务与云资源开通**：机审/IM 等三方服务选型 + 云资源规格与开通主体（供应商账号与用量由 PM 方确认）
7. **P0 三项责任人**各定一位与截止时间
8. **数据闭环推演缺口表**逐行批注（推测与设计意图不符处）

跟踪台账：[待确认事项台账](../../context/pending-confirm.md)——批复后逐条处理，不删行。

## 四、最需要你配合的三件事

1. **运营商/校方渠道对接**：对接需求清单已备好（[三方对接需求清单](../requirements/三方对接需求清单.md)），走校方行政还是运营商商务渠道由你定——这是排期最大风险，第一周就该动
2. **顶 UI 对应确认**：UI 机动不固定（不驻场），80 张设计稿与正文未对应的 10 处需你逐条确认
3. **冻结需求**：批完 §三 再进冲刺；之后新增需求一律走变更流程排二期，不在一期周期内吸收
