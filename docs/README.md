# 工程文档索引

## requirements/（需求域）

- [需求文档评估](requirements/需求文档评估.md) — 对根目录需求文档 1.0 的评估：P0 阻塞项、合规风险、跑腿状态机缺口、工作量粗估与下一步行动
- [需求覆盖度清单](requirements/需求覆盖度清单.md) — 已有覆盖面（UI 全链路 + 后台配置层）与缺失三层（后台管理层/平台层/非功能层）对照，供 PM 确认补齐优先级
- [自建服务难度评估](requirements/自建服务难度评估.md) — 按基础服务/平台/业务/后台四层评估自建难度与自建/采购/先验证策略，附优先级依赖关系
- [数据闭环推演](requirements/数据闭环推演.md) — 八个数据域逐项追踪来源与去处，标注未闭合缺口与闭合推测，孤儿数据双向盘点
- [缺失补全方案](requirements/缺失补全方案.md) — 按行业惯例对全部缺口给出默认规则与数值（碎银经济/资金链路/账号/审核/订单/孤儿处理意见/后台/非功能），附 PM 确认清单
- [端与交付物清单](requirements/端与交付物清单.md) — 「一 App 一后台」端划分：用户端 12 功能包、后台 9 功能包、客服坐席可裁、三方依赖端降级路径，附交付物工作包表
- [三方对接需求清单](requirements/三方对接需求清单.md) — 运营商/校方、支付、机审三条外部接入线的接口需求、材料清单与降级预案，附执行跟踪表
- [开发区域划分](requirements/开发区域划分.md) — 模块 → 功能点 → 开发区域映射表：12 业务模块 + 8 后台模块 + 平台层归入 App-1/App-2/后端 A/B/C 与机动位，含分期标注
- [云原生架构与部署方案](requirements/云原生架构与部署方案.md) — 后端云原生托管的模块化单体：架构定位、资源规格、多校 SaaS 演进触发条件（技术栈与选型方案的部署篇，选型正文在 internal/）

## decisions/（决策域）

- [项目决策与不确定项](decisions/项目决策与不确定项.md) — PM 确认唯一入口：已确认事实（F1~F7）+ 结构性决策（D1~D8）+ 执行层决策（N1~N11）；批注后由辅助工具回填源文档并派生 PM 域

## PM/（PM 交付域 · 派生域）

> 本域均为其他域文档的派生件，源文档为正身；源实质修改后须刷新对应派生件。

- [项目说明-给PM](PM/项目说明-给PM.md) — 一页纸总览：全局判断、已确定、待确认 8 项、需 PM 配合三件事、文档导读；PM 入口文档
- [项目总览-对外交付版](PM/项目总览-对外交付版.md) — 可直接对外交付的完整文档：现状/范围分期/人力/排期/外部依赖/待确认/技术形态全内联，不挂外部链接；排期到里程碑，不含功能点工期拆解

- [PM结论汇总-给PM](PM/PM结论汇总-给PM.md) — 各文档「给 PM」结论小节的 辅助工具归并版（去重、统一说法、每节带来源路径）；单独发 PM 用这份
- [PM结论汇总-原始](PM/PM结论汇总-原始.md) — `toolbox run pm-conclusions` 机械汇总的原始小节，供溯源；可随时重新生成
- [排期与里程碑计划-给PM](PM/排期与里程碑计划-给PM.md) — 兼职档投入前提与外部周期说明、M0~M1 里程碑表、分期范围与降级预案
- [工期评估-按功能点-给PM](PM/工期评估-按功能点-给PM.md) — 业务模块 + 后台模块逐功能点的服务端工期拆解（三人并行、人均每周 3 天、含 20% 测试，总工期约 6.5~7 个月）

## coord/（协调域 · 派生域）

> 读者是客户方协调人员（不是决定者）：每项带确认人/协调材料/时间门槛/后果四要素，批注结论回流决策文档。

- [协调事项清单-给协调人](coord/协调事项清单-给协调人.md) — 8 项结构性决策 + 三条外部对接线的推动顺序，每项四要素（确认人/材料/时间门槛/后果），附材料就绪表与已定事项
- [对接函-校园网校园卡](coord/对接函-校园网校园卡.md) — 校方/运营商对接函底稿（一页：产品介绍 + 数据用途 + 隐私说明 + 技术对接形式），渠道确定后出正式版
