# 校乐趣 · 协调事项清单（给协调人）

> **代号说明**：D1~D8 = 8 项结构性决策（M0 冻结门）；N1~N11 = 执行层决策；F1~F7 = 已确认事实；M0 = 启动前准备阶段（3 周，起点以八项清单批完之日计）；S1~S3 = 三个开发冲刺（各 7 周）；MVP = 首版上线范围；T0 = M0 完成日；「建议值」= 开发侧给出的建议，不是结论。

> **来源（归并自）**：[项目决策与不确定项](../decisions/项目决策与不确定项.md)、[排期与里程碑计划-给PM](../PM/排期与里程碑计划-给PM.md)、[三方对接需求清单](../requirements/三方对接需求清单.md)（updated 2026-10-14）。本文为派生件，结论以决策文档为准。

## 结论（给协调人）

- **判断**：开发侧能提前做的准备已完成（需求补全方案、排期、对接需求清单、对接函底稿）；当前卡在 **8 项结构性决策与三条外部对接线**，其中运营商/校方线周期最长（审批按以往经验需 1~3 个月）、影响最大（接口拿不到则核心价值降级）。
- **推动顺序**：① 运营商/校方接口——第一周发出对接函；② 支付资质——并行申请；③ 机审选型——M0 内完成；④ 八项决策批注——M0 冻结门，批完才进冲刺。
- **时间门槛**：M0 为 3 周，起点以八项清单批完之日计；一期 MVP 上线 T0 + 6.5~7 个月、全量 9~10 个月，均以人均每周 3 天投入为前置（决策文档 F3/F4）；运营商接口最迟 M0 内发出对接函，再晚则总排期整体后移。
- **已定事项不必再确认**：人力（3 后端 + 2 App）、投入档（人均每周 3 天）、一期范围（8 包）、孤儿功能归属（二期）均已确定，见下文「已定事项」。

## 批注后怎么流转

1. 协调人把确认人的结论带回开发侧（口头或文档形式均可）；
2. 开发侧把结论回填决策文档「PM 确认」列与对应源文档，刷新源文档 updated；
3. 源文档实质修改后，刷新对应 PM 域派生件；
4. 已确认事项移入决策文档「已确认事实」表（新增 F 编号、带日期留档），不删除。

> 每轮协调后请把各事项进展（已确认 / 推进中 / 未回应）同步开发侧，开发侧会更新决策文档状态列与三方清单执行跟踪表。
