# 需求覆盖度清单

## 结论（给 PM）

- **判断**：需求文档 1.0 覆盖了**用户侧 UI 全链路**（17 章 + 80 张设计稿），并收了**后台配置层 5 块**——但离可开发的完整需求还差**三层**：后台管理层、平台层、非功能层。
- **后台现状**：第十六章已有 Banner/广告、碎银商城、通知、跑腿（含提现审核）、用户管理；缺财务对账/退款、内容审核工作台、数据报表、风控、后台权限分级与审计。
- **最大的洞在平台层**：账号体系、资金合规、校园网/校园卡对接三项是 P0，不定下来工作量与排期都是虚的。
- **需要你确认**：三层缺口的补齐优先级，以及 P0 三项各定一位责任人与截止时间。

## 与 PM 确认的优先级建议

1. **先确认 2.2 平台层**（A1~A4）：不定技术形态、对接方案与合规路线，开发无法估工作量。
2. **后台五块（B1~B5）随对应业务排期**：内容审核工作台与财务后台必须随 UGC/交易模块同期上线，不能后补。
3. **非功能层在开发启动前补一份基线**：N1 隐私合规件随上架流程推进，N4 埋点随首版设计定埋点表。
