# 端与交付物清单

## 结论（给 PM）

- **端总数：2 个自研端（3 个交付物）+ 3 个外部依赖端**——用户端 APP（iOS/Android 双平台）+ Web 运营后台；客服坐席首版用后台替代，不独立建端。
- **工作包划分**：本文即开发团队的任务划分表——App 双平台各一个工作包、后台一个工作包、三方接入三条线（运营商/支付/机审）。
- **外部端不自研但决定闭环**：流量域（运营商）与资金域（支付通道）的接口不通，对应功能只能降级上线（见[自建服务难度评估](自建服务难度评估.md) §六）。
- **需要你拍板**：已确定（2026-10-13）——**后台管理页面由后端直接接管，不设常驻前端；常驻开发组 3 后端 + 2 App，前端机动，UI 机动不固定（按需支持，不驻场）**；剩余待确认项仅「iOS/Android 同步交付还是分阶段」。
- **排期标准（2026-10-13 定）**：开发团队为**兼职投入，人均每周 3 天**（投入上限档）；本档下排期按满负荷测算，排期为**一期 MVP 约 5.5~6 个月、全量约 8~9 个月**。所有月数均以「人均每周 3 天」为前置条件，投入降档即重排。

## 〇、总览

```
校园圈产品
├── 自研端 1：用户端 APP（iOS / Android 双平台，同一套功能）
├── 自研端 2：运营管理后台（Web，单端三角色）
├── （轻量）客服坐席：首版由后台「投诉管理 + FAQ」替代，不独立建端
└── 外部依赖端 ×3：运营商/校方系统、微信/支付宝、机审服务
```

- 角色差异（访客/校园网用户/校园卡用户、发布者/接单者、榜一）全部在用户端内以**功能开关**实现，不产生独立端。
- 客户端技术形态（原生/Flutter/小程序）未定（评估 P0 #1），本文按功能包划分，与形态无关。

### 6.2 排期粗估

### 6.4 坑位再平衡结论（2026-10-13 确定）

- **常驻编制 5 人：3 后端 + 2 App；前端机动编制；UI 机动不固定**（后台页面日常归后端 B，复杂交互页按需引入机动前端；UI 按里程碑节点支持，见 6.1）。
- 后端线经兼职换算（3 天/周）后 5.5~7 个月贴着 6 个月窗口走——**排期按满负荷测算**：保底测试、后台页面接管、三方等待期均已计入。
- App 线双人分包后全量 ~8 个月，与后端线基本对齐——两条线排期均按满负荷安排。
- 剩余增员建议仅一项：**+1 测试**（专保资金链路与跑腿状态机回归）；不建议再加后端。
