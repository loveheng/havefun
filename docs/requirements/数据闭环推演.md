# 数据闭环推演

## 结论（给 PM）

- **判断**：需求文档把「界面上的数字」都画出来了，但**一半以上的数字没有交代来源或去处**——最典型的是碎银：8 个获取渠道无一有数值与上限，8 个消耗出口无一有定价规则。
- **三类未闭合**：①无来源（优惠券/电子券、商户角色、餐厅点餐、任务中心）；②无去处（扫一扫）；③有来源有去处但中间规则缺失（碎银兑换率之外的定价、二手资金是否过平台）。
- **闭合优先级**：碎银账本规则 → 资金链路过不过平台 → 校园网数据接口——这三条不闭合，开发写不出第一行结算代码。
- **需要你拍板**：下表每行「缺口」列的推测若与你的设计意图不符，请逐行批注。

## 〇、读法说明

- 每个数据项按 **来源（谁产生/从哪同步）→ 去处（在哪消费/展示）** 双向追踪；任一端缺失即「未闭合」，给出**闭合推测**（标 ⚠ 为推测，需 PM 确认）。
- 「缺口」分四级：🔴 无来源/无去处（孤儿数据）｜🟠 两端都有但规则缺失｜🟡 有规则但数值/口径未定｜⚪ 依赖外部接口。
- 章节引用格式「§4.4」指[需求文档](../../需求文档.md)对应小节。

### 9.3 闭合优先级（开发阻塞序）
