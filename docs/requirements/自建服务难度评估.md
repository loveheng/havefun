# 自建服务难度评估

## 结论（给 PM）

- **判断**：真正「必须自己写且难」的只有四块——**校园网/校园卡对接、资金链路、碎银账本、跑腿交易闭环**；其余大部分服务（IM/推送/短信/机审/存储）**能买不建议自建**。
- **最大风险**：校园网对接不是难在开发，是难在**数据源可能根本拿不到**（依赖运营商/校方接口）——这是排期前必须先验证的第一件事。
- **合规门槛**：资金链路（支付/提现/二清）与内容审核是上架前提，不是优化项。
- **需要你确认**：① 校方/运营商接口能否获取（决定核心价值是否成立）；② 资金走持牌通道还是劝阻人民币链路；③ 三方服务选型（IM/机审）。

## 评估标准

- **难度分级**：🟢 低（标准集成，天级）｜🟡 中（常规开发，周级）｜🟠 高（复杂逻辑/多方协调，月级）｜🔴 极高（外部依赖主导或合规底线）。
- 依据：[需求文档](../../需求文档.md) 1.0 快照 17 章 + [需求文档评估](需求文档评估.md) P0/P1 清单 + [需求覆盖度清单](需求覆盖度清单.md) 缺口三层；技术形态（原生/小程序）未定（评估 P0 #1），下列估级按「工作量不因形态剧烈变化」的功能块标准给出。
- 「建议」列区分三种策略：**自建**（无现成方案，必须写）、**采购**（三方成熟服务）、**先验证**（能不能做取决于外部资源，先确认再谈开发）。

## 基础服务层（能买则买）

| 服务 | 需求出处 | 自建难度 | 评估与建议 |
| --- | --- | --- | --- |
| 短信验证码 | 注册/找回（设计稿有、正文无） | 🟢 低 | 采购云厂商；不自建 |
| 消息推送 | 10.4 推送场景 | 🟢 低 | 厂商通道聚合（APNs/华为/小米等）或个推类服务；自建推送通道不值得 |
| 图片/文件存储 | 二手商品图、作品、Banner | 🟢 低 | 对象存储 + CDN 采购 |
| IM/在线聊天 | 10.4「商户客服/在线聊天」（孤儿需求） | 🟠 高 | 自建 IM（长连接/离线/多端同步）人月起；**建议融云/环信等采购**，随订单卡片消息定制 |
| 支付接入 | 5.5/11.4 人民币模式、活动差价补款 | 🟡 中 | 微信/支付宝支付 SDK 是标准集成；**难点不在接入在资金合规**（见本文『平台层』A2） |
| 激励视频广告 | 4.6 看广告赚碎银 | 🟡 中 | 穿山甲/优量汇 SDK 集成为主；注意媒体账号资质门槛与「虚拟奖励」平台规则 |

## 平台层（自建为主，含合规底线）

| 服务 | 需求出处 | 自建难度 | 评估与建议 |
| --- | --- | --- | --- |
| 账号体系 + 学号认证 | 全文（设计稿有正文无，P0 #4） | 🟡 中 | 注册/登录/Token 是标准件；难点在学号唯一性与多校区数据隔离（P1 #12），需先定单校还是多校 SaaS |
| 校园网/校园卡对接 | 3.3 卡状态/上下线、碎银出账依赖流量数据 | 🔴 极高 | **先验证**：数据来自 RADIUS/portal/计费系统，接口归属运营商或校方。拿不到接口则「刚需入口」与碎银产量规则同时落空——全项目第一优先级前置项 |
| 资金链路（归集/提现/对账） | 5.5 跑腿报酬预付、14.3 余额、16.4 提现审核 | 🔴 极高 | 平台碰人民币归集即涉二清，**必须走持牌通道**（微信服务商分账/银行存管）或改造为不碰钱的模式；结算/退款/对账系统本身人月级自建 |
| UGC 内容审核 | 六/七/十一 全部 UGC 场景（P0 #5） | 🟠 高 | 策略：机审**采购**（数美/易盾等，文本/图/视频）+ 人审工作台**自建**（含敏感词库、举报处置流水）；先发后审还是先审后发需 PM 定 |
| 碎银经济系统 | 第四章全章 + 16.5 手动调整 | 🟠 高 | 自建账本：获取渠道 8 种、按月出账清零、有效期（待定 #4）、赠送/抵扣/盲盒多出口；**必须配套**每日上限与反刷规则（评估 P1 #9），否则上线即通胀 |

## 后台管理（对应覆盖度清单 B1~B5）

| 模块 | 自建难度 | 评估 |
| --- | --- | --- |
| 内容审核工作台 | 🟡 中 | 常规 CRUD 工作台 + 机审结果处置流；随 UGC 同期上线 |
| 财务/对账后台 | 🟠 高 | 退款、结算对账、异常账务——复杂度随资金链路方案走，方案未定前无法开发 |
| 风控后台 | 🟡 中 | 规则配置 + 黑名单；规则本身需运营定义 |
| 数据报表 | 🟡 中 | 依赖埋点先完成（覆盖度 N4），否则无数据可报 |
| 权限分级 + 审计日志 | 🟢 低 | 常规 RBAC + 操作流水 |

## 优先级与依赖关系

1. **先验证再估期**：校园网对接（拿不拿得到接口）→ 资金合规路线 → 多校/单校。三项任一未定，相关模块估级都会翻倍或归零。
2. **可并行的采购项**（不阻塞开发）：短信、推送、存储、IM、机审——选定供应商后均为集成工作。
3. **建议的自建顺序**：账号体系 → 碎银账本（含风控规则）→ 商城/社区 → 跑腿闭环（最后做，依赖前面所有地基 + 状态机补全）。

> 结论提炼自需求文档 1.0 与[需求文档评估](需求文档评估.md)；难度为工程量级判断，非排期依据——正式排期需在 P0 三项（技术形态/对接/合规）确定后重估。
